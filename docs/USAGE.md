# 使用指南

Paper-easy 1.0.0 · Nanoarcheaum

## 阅读与批注

- 左侧“批量导入论文”：每篇可选不同目录，创建“论文名/论文名.pdf + 论文名.md”，笔记带 Paper 标签。Paper 文件树汇总这些笔记、PDF 和目录；正文 #Paper 加同名 PDF 也可识别。
- 从 Paper 文件树或“打开论文与伴随笔记”打开时，PDF 保持在左，伴随笔记在右；记录内容不会替换正在阅读的 PDF。
- **选中文字后右键**：第一行是四色、高光、下划线、删除线和文字批注；第二行是引用到笔记、复制原文链接、截图、翻译。Esc 或点击外部关闭。
- 文字引用与截图均直接写入简洁引用块，保留页码回链与块 ID。截图框选后直接保存到论文旁的 figures 目录，不填写图注表单。
- 在其他 Markdown 中运行“插入论文块引用”，可搜索文字、截图和原生批注。新格式把内容和页码放在同一个结构块内；旧摘录保持兼容，可选择运行“修复当前论文旧摘录的块引用”，保持原有 ID。
- 高光、下划线、删除线、文字批注以及可选的翻译高光均写入 PDF。批注管理支持编辑文字、改色、删除；新批注同时保留所选原文便于辨认。已有批注右键可直接进入编辑或删除。
- 右侧“论文批注”边栏检索完整原文、译文、评论和截图文件名，按笔记路径区分同名论文，记住分组折叠状态，可复制块引用或收起边栏。其索引来源是 Paper 笔记；外部 PDF 批注可在当前 PDF 的批注管理中查看，不自动导入全库索引。
- 使用 Obsidian 原生横向滚动条，没有自定义底部滑块。

常用快捷键：`Ctrl/Cmd + Shift + E` 摘录，`Ctrl/Cmd + Shift + G` 截图，`Ctrl/Cmd + Shift + T` 翻译选段。右键提供更直接的选区操作。

## 保存、删除与恢复

PDF 批注按文件串行写入，写入前检查文件是否已改变。每次操作先保存原 PDF 与笔记修改记录，再写 PDF 和 Markdown；编辑／删除会先核验来源块边界，无法识别时不删除手写内容。

- **恢复未完成的批注同步**：补齐 PDF 已保存但笔记未完成的操作；也可补齐导入、截图、文字摘录的未完成记录。若文件已移动或笔记有后续编辑，将保留记录并报告，避免覆盖用户内容。
- **撤销当前论文上一次批注操作**：仅在 PDF 与笔记仍匹配保存后状态时恢复。包括删除、改色及旧引用边界修复。连续使用可能切换回上一次状态，不是多级撤销栈。
- 删除插件创建的 PDF 批注仍会删除对应笔记来源块，因此引用它的其他笔记可能暂时出现缺失块；可在发生后续修改前撤销。
- 恢复数据位于插件目录的 `recovery`、`pending-notes`、`pending-imports`。recovery 每篇保留最近三次完成操作的备份，未完成记录不自动清理。不要把这些目录与升级包一起覆盖或删除。

多文件保存不是文件系统原子事务；检查与 PDF 写入之间仍存在极短的外部写入竞争窗口。若需要两边同时编辑同一 PDF，应避免在保存瞬间由另一阅读器写入。备份用于故障恢复，不应替代自己的 Vault 备份。

## 选段翻译

保留用户已有 endpoint、模型和密钥。新配置默认是 `http://localhost:11434/api/chat`、`qwen3:14b`、简体中文；这只是默认值，不表示本机服务已经运行。已有 Ollama 不需要重新安装。

Ollama 请求关闭思考、保持模型常驻 30 分钟；同一接口／模型／语言的重复选段在当前会话缓存（最多 64 条）。只发送选段，不发送整篇 PDF；等待有 90 秒上限，关闭或切换后的迟到结果不会再弹出。关闭 UI 使结果失效，不保证中止服务端推理。超过 6000 字符的选段会提示拆分；模型报告截断时不把残缺译文作为成功结果。

选择“生成翻译批注”会保存标准 PDF 高光及其译文，并写入伴随笔记，重新打开仍有数据。此前仅保存在文本层的临时翻译标记不能凭空恢复坐标；旧笔记中的译文仍可检索。实际速度取决于用户模型和机器，本版未测本机 Ollama 延迟。

## Zotero 可选兼容

启用兼容模式后使用本机 API，不访问 Zotero 数据库。题录从 Zotero 单向更新 Markdown；共享的是 PDF，Zotero 数据库批注不做双向同步。

同步优先匹配已保存的附件 key，其次完整路径／基目录相对路径；没有可用路径时仅允许唯一文件名匹配。同名或冲突附件会跳过，不猜测关联。使用基目录相对链接时应将基目录设为 Vault 根目录。

“将当前论文链接到 Zotero”在笔记中保存待完成的条目 key；部分成功或响应不明时重试会核对已存在的记录，只补缺失项。题录和附件都确认成功后才保存完成关联。需要服务支持本地写入并由 Zotero 授权，读取和写入能力以实际服务为准。逐项核验遵循 [Zotero 写入结果格式](https://www.zotero.org/support/dev/web_api/v3/write_requests)。
